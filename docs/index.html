C++ implementation of a linear perpetuals market maker

A C++17 project that combines a public market-data client for Binance USD-M Futures, inventory-aware one-way quote planning, a demo-order path restricted to the official demo REST host, and a historical backtester that replays official daily files with simulated fills.

Architecture

CMake-based C++17 project. Core library sources live under src/ with headers in include/mm/.

  • Quote planning — Inventory-aware spread, fee floor, gross cap, reduce-only take-profit and stop logic as one-way quotes (src/quote.cpp).
  • Order book — Local book synchronized to Binance USD-M diff-depth rules: snapshot lastUpdateId, bridge the first event with U ≤ id ≤ u, then require pu == previous u. Stale updates and gaps trigger resync (src/order_book.cpp).
  • Market data — Public REST and WebSocket only. Depth snapshots requested only after production REST returns HTTP 200. HTTP 451 is reported and not bypassed. Reconnects limited (src/live.cpp, src/net.cpp).
  • Demo orders — Restricted to https://demo-fapi.binance.com after a successful demo ping and only with BINANCE_DEMO_API_KEY / BINANCE_DEMO_API_SECRET. No path sends orders to the production host. On shutdown, cancel-all is attempted and open orders are reconciled before reporting (src/demo.cpp, src/live.cpp).
  • Historical backtest — Downloads official daily files from data.binance.vision, verifies SHA256, replays aggTrades with a latency-delayed strict-through fill model, applies funding when present, and writes reports (src/backtest.cpp, src/history.cpp, src/report.cpp).
  • Tests — Unit tests cover order-book sequence handling, quote planning, demo URL guards, filter parsing, fill simulation, and zip round-trip (tests/unit_tests.cpp).

See the src and include/mm directories for the implementation.

Backtest

The backtester consumes official Binance daily files for a given symbol and date. Required filters (--tick, --step, --min-qty) must be supplied by the operator when exchangeInfo is not used. A maker fill is recorded only when a real aggTrade prints strictly through the quote after the configured latency, and the fill quantity cannot exceed that print. Touches at the quote price are counted but not filled. bookDepth data is percentage-bucket depth, not a full tick book. Missing funding files remain missing.

./build/binance_backtest \
  --symbol BTCUSDT --date 2026-10-19 \
  --tick 0.1 --step 0.001 --min-qty 0.001 --min-notional 50 \
  --budget 1000 --max-net-qty 0.01 --latency-ms 200 \
  --maker-fee 0.0002 --taker-fee 0.0005 \
  --data-dir data --out reports/btcusdt-2026-10-19

Outputs are local. Queue position is not modeled. Latency, fees, and historical depth limitations apply. Results are not exchange executions.

Validation and limitations

Build and run the existing unit tests:

# Ubuntu
sudo apt-get install -y build-essential cmake ninja-build libssl-dev zlib1g-dev
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure

Public market-data check (no orders):

./build/binance_market_maker --check --symbol BTCUSDT

Demo orders are possible only with explicit --demo, a successful demo ping, and demo credentials. The process attempts to cancel outstanding demo orders and reconcile open orders on exit. If confirmation fails, a warning is emitted that exchange-side orders may remain.

  • Simulated fills ≠ exchange execution.
  • No modeling of queue position.
  • Fixed latency and fee assumptions.
  • Historical depth is bucketed; full L2 is not reconstructed from the daily files used.
  • Unit tests validate logic and guards; they do not validate trading profitability.
  • No live production order path exists.
